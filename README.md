Приложение разрабатывается для удовлетворения потребностей в области анализа данных и визуализации расчетов.

**Основные задачи** это машинное обучение и классификация данных скважин, по данным геофизики

**Второстепенные задачи** - работа с данными, сортировка, анализ, обработка;
                            построение структуры по данным сейсмики или по данным ЗСБ.

Stack:
- Python 3.12
- PyQt6
- PyVista
- NumPy
- Pandas

## Запуск

На каждом компьютере установите 64-битный Python 3.12 и запускайте из корня
проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

Версия Python задана в `.python-version`. Скрипт проверяет локальный `.venv`,
при необходимости восстанавливает его, устанавливает закреплённые версии из
`requirements.txt` и проверяет их совместимость. Для проверки без открытия окна
добавьте `-CheckOnly` в конец команды. Если Python установлен, но скрипт не
находит его, задайте переменную `X_SEARCH_PYTHON` с полным путём к рабочему
`python.exe` и повторите запуск.

В IDE выберите интерпретатор `<папка проекта>\.venv\Scripts\python.exe`.
При переносе проекта копируйте исходники и `requirements.txt`, но не `.venv`:
виртуальное окружение содержит абсолютные пути и создаётся заново на каждом ПК.
Для 3D нужен рабочий OpenGL-контекст Windows. Платформа Qt `offscreen`
используется только в тестах интерфейса с заменой 3D-вьювера.

## Сборка Windows EXE

На Windows выполните из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-exe.ps1
```

Готовый файл находится в `dist\XSearch.exe`. В него включены Python,
библиотеки, файлы интерфейса и изображения, поэтому для запуска на другом
компьютере Python устанавливать не требуется. При первом запуске распаковка
может занять некоторое время. Для 3D-визуализации по-прежнему необходима
поддержка OpenGL на компьютере пользователя.

## Работа с проектом

1. **Файл → Создать проект**: выбрать родительскую папку и ввести имя.
2. **Импортировать объект**: выбрать тип в выпадающем списке, затем CSV/TXT/DAT,
   разделитель и наличие заголовка, назначить три разные числовые колонки X/Y/Z
   и дополнительные параметры. Для скважины и файла скважин нужно выбрать колонку
   идентификатора; для поверхности — вид («обычная», «разрез», «трещина»).
   Для файлов без заголовка используются имена колонок `0`, `1`, `2` и т. д.
   Поверхность можно также импортировать из VTK/VTP/STL/OBJ/PLY/VTU/VTS.
   При импорте поверхности из таблицы используется геометрия XYZ; дополнительные
   столбцы не назначаются параметрами поверхности. XYZ-точки триангулируются
   автоматически; если нужно сохранить точную топологию разреза или трещины,
   импортируйте готовую сетку.
   Основной тип импорта — **Точки с настраиваемой сеткой**. Табличные данные
   сохраняются как точки; при необходимости сетка создаётся для отображения.
   Для **куба данных** CSV/TXT/DAT трактуется как облако **центров ячеек**.
   В поле «Сетка куба» по умолчанию выбран corner-point grid: если XYZ образуют
   ряды и слои, одна точка соответствует одной ячейке; пропущенные ячейки
   неактивны. Для нерегулярного облака строится равномерная сетка по габаритам
   точек. Число ячеек X/Y/Z можно задать вручную или оставить «Авто»; параметры
   точек в общей ячейке усредняются, а `N_POINTS` хранит их количество.
   Флажок «Соединять существующие ячейки» по умолчанию расширяет ячейки через
   пустые интервалы до общей границы. Новые ячейки не добавляются, исходные
   параметры сохраняются. Для разреженного облака расширение выполняется вдоль
   преобладающего горизонтального направления и по вертикали в каждом столбце;
   между несопоставимыми рядами пустоты могут остаться.
   Исходные координаты центров сохраняются как `CENTER_X/Y/Z` (при нескольких
   точках в ячейке — их средние). При неравномерном расстоянии между рядами
   геометрический центр построенной ячейки может отличаться от исходной точки.
   Если по оси есть лишь один уровень центров, её толщину задаёт поле
   «Размер ячейки по одиночной оси». Границы между рядами ставятся посередине
   между соседними центрами; геологические разломы и наклонные пиллары из одних
   центров автоматически не восстанавливаются. Для прежнего отображения без
   ячеек есть режим «Только точки».
   Режим **«Послойная модель (кровля/подошва)»** создаёт один общий узел куба и
   дочерний corner-point куб для каждого значения выбранной колонки слоя.
   Выберите колонки X, Y, слоя, кровли и подошвы; `layer`, `AbsRoof` и `AbsBase`
   распознаются автоматически. Слои нумеруются сверху вниз по медианной
   абсолютной отметке кровли среди всех пикетов; исходное название слоя
   сохраняется в дереве и свойствах. `LAYER_INDEX` доступен как параметр ячеек.
   Геометрия каждой ячейки строится между кровлей
   и подошвой, параметры строк остаются доступными для окраски. Слои можно
   независимо показывать и скрывать в дереве; проект сохраняет их отдельно.
   Для нерегулярной XY-сетки число ячеек X/Y можно задать вручную. Высоты углов
   общих ячеек усредняются из соседних значений кровли и подошвы.
   Файл `all.dat` с колонками `PKX`, `PKY`, `layer_id`, `layer_AbsRoof` и
   `layer_AbsBase` распознаётся как послойные интервалы точек. При импорте читаются
   только строки интервалов по пикетам; повторяющиеся строки выборки по `H`
   не загружаются в куб. Числовые параметры `layer_*` можно выбрать для окраски.
   Для **куба данных** можно также выбрать `.grdecl`: тип переключится на куб,
   а геометрия `SPECGRID`/`DIMENS`, `COORD`, `ZCORN`, маска `ACTNUM` и числовые
   параметры ячеек будут прочитаны автоматически. Предпросмотр показывает центры
   активных ячеек и индексы I/J/K; назначать колонки вручную не требуется.
3. В контекстном меню дерева можно создавать вложенные папки, импортировать
   данные в выбранную папку, переименовывать и удалять объекты. Флажок папки
   управляет видимостью всего её содержимого; настройки видимости детей сохраняются.
   Пункт **«Разведочный анализ (EDA)…»** открывает анализ выбранного объекта,
   файла скважин, послойного куба, папки или всего проекта. Выберите числовые X, Y и Z,
   рядом с каждым параметром задайте линейный или логарифмический масштаб,
   при необходимости выберите класс, отметьте графики и нажмите «Построить графики».
   Настройки находятся слева, прокручиваемые графики — справа; ширину панелей
   можно менять разделителем.
   Для логарифмического масштаба используются только положительные значения.
   Доступны ящик с усами, плоское и трёхмерное рассеяние, скрипичная диаграмма, точки по группам,
   ECDF, гистограмма, KDE, двумерная и трёхмерная гистограммы, матрица корреляций.
   На матрице одинаковый цвет означает одинаковую силу положительной и отрицательной связи.
   Вкладка «Статистика» показывает описательные показатели. Для объектов с более
   В списке «Данные» можно выбрать быструю выборку до 200 000 строк или все записи.
   Режим «Все записи» использует полный набор строк для графиков и статистики;
   на очень больших объектах построение может занять больше времени.
4. **Сохранить** (`Ctrl+S`) записывает данные и структуру. Звёздочка в заголовке
   показывает несохранённые изменения. **Сохранить как** создаёт самостоятельную
   копию в новой или пустой папке и переключает работу на неё.
5. При закрытии окна, закрытии проекта, создании или открытии другого проекта
   предлагается сохранить изменения, отбросить их или отменить действие.
   Ошибка сохранения также отменяет закрытие.
6. При следующем запуске восстанавливается последний открытый проект.
   **Закрыть проект** очищает текущую сессию; после этого автоматического открытия
   не будет. Вручную проект открывается через его `project.json`.

Для переноса проекта нужно копировать **всю папку проекта**. После сохранения
исходный CSV больше не требуется для восстановления данных.

Типы объектов: **скважина** хранит упорядоченную траекторию, ID и числовые
параметры каждой точки; **файл скважин** группирует скважины по ID и позволяет
получить скважину по идентификатору; **куб данных** хранит 3D-узлы и параметры
либо corner-point grid с пилларами, независимыми глубинами углов, маской активности
и параметрами ячеек. Куб поддерживает разрезы по X/Y/Z, а для полного набора
регулярных узлов — построение плотного массива;
**поверхность** хранит треугольную сетку и её вид, вычисляет площадь; **облако
точек** остаётся свободным набором точек. Тип, параметры и дочерние скважины
сохраняются в проекте. Узловой куб отображается точками, corner-point grid —
объёмными ячейками с рёбрами, скважина — линией траектории.

GRDECL поддерживает повторения вида `N*значение`, включая `D`-экспоненту,
`INCLUDE` с путями относительно файла и числовые массивы параметров длиной
`Nx×Ny×Nz`. Для файлов `INCLUDE` используется порядок следования данных I, J, K
с самой быстрой осью I. Отсутствующий `ACTNUM` означает, что все ячейки активны.
Геометрия и параметры копируются в проект, поэтому после сохранения исходный
GRDECL и вложенные файлы не нужны. Операции `MAPAXES`, `BOX`, `EQUALS`, `COPY`,
`ADD`, `MULTIPLY`, локальное уточнение сетки и бинарный EGRID пока не
поддерживаются: импорт таких геометрических преобразований прерывается с ошибкой.

### Настройки отображения

Основной тип импорта **Точки с настраиваемой сеткой** хранит
таблицы точек, назначение слоёв и настройки отображения. Corner-point геометрия
вычисляется в памяти для просмотра и не записывается как куб в проект.
Прежние варианты облака точек, узлового куба и послойного куба доступны отдельно.

Большие таблицы читаются в фоне, в окне импорта показывается ход загрузки;
чтение можно отменить. Длительное построение сетки также выполняется в фоне:
в строке состояния виден прогресс и доступна отмена, а скважины и другие объекты
можно показывать или скрывать во время расчёта. При повторном открытии проекта
сначала показываются исходные точки, затем автоматически восстанавливается сетка.
Готовая геометрия скрытых объектов остаётся в памяти до закрытия или полного
обновления сцены; повторное включение не требует её пересчёта.

В новом варианте выберите структуру при импорте: исходные XYZ; исходные XYZ
с разделением по колонке слоя; либо интервалы слоёв из XY, кровли и подошвы.
В последнем случае точка представляет середину интервала; исходные колонки
таблицы сохраняются. Для Мамырского DAT с `layer_id` и `layer_AbsRoof/Base`
интервалы читаются отдельно от строк дискретизации H. Для просмотра исходных
отметок H выберите структуру XYZ, укажите PKX, PKY, H и при необходимости
разделите точки по колонке `lid`.

После импорта выберите объект или контейнер слоёв. В панели **Отображение**
доступны точки, сферы, **Corner-point grid** и его каркас. В блоке
**Сетка отображения** задайте размеры ячеек XYZ и нажмите
**Построить / перестроить**. Для новых объектов по умолчанию выбрана
**Интерполяция IDW**: соседние ячейки имеют общие угловые узлы и образуют
связанную поверхность. У интервалов кровля и подошва интерполируются в узлах
общей XY-сетки; параметры интерполируются в центрах ячеек. Слои используют
одну XY-разбивку, но каждый слой интерполируется по собственным точкам.
**Радиус интерполяции** задаётся в единицах координат: расстояние в XY для
интервалов и в XYZ для объёмных точек. Используются до 32 ближайших точек
в пределах радиуса с весами 1/d². Вне покрытия полные ячейки не строятся,
поэтому большие промежутки между профилями не заполняются при малом радиусе.
Нулевой радиус означает автоматический подбор. Число ячеек X/Y/Z задаёт
разрешение сетки; для интервалов разбивка по Z определяется слоями.
В уже сохранённом объекте выберите **Интерполяция IDW** вручную, чтобы
перейти с прежних отдельных ячеек на связанную поверхность.
Вариант **Отдельные ячейки у точек** сохраняет одну ячейку на исходную точку
без усреднения; размеры XYZ регулируют только эти отдельные ячейки.
Режим **Равномерная сетка с усреднением** позволяет задать число ячеек XYZ;
усреднение применяется только к временному отображению. Слои строятся
независимо и сохраняют свои имена, видимость и исходные строки при перестроении.
Направление Z задаётся при импорте и в блоке **Сетка отображения**:
**Высоты: Z вверх** или **Глубины: Z вниз**. Для интервалов автоматический
режим определяет направление по кровле и подошве. Для обычных XYZ авто
означает высоты; для глубин выберите направление явно. При выборе глубин
координата отображается как −Z; исходная таблица не меняется. Направление
применяется одинаково к точкам и ячейкам и сохраняется в проекте.

Выберите объект в дереве. Справа, под таблицей свойств, находится панель
**Отображение**. После импорта облако точек выбирается автоматически.
Если выбран **файл скважин** или **послойный куб**, изменения этой панели,
включая палитру, сразу применяются ко всем дочерним скважинам или слоям.
В редакторе палитры контейнера доступны только числовые параметры, общие для
всех его дочерних объектов. Настройки контейнера и детей сохраняются в проекте;
добавленный позднее объект наследует текущий вид контейнера.

У скважин рядом с началом траектории показывается их идентификатор. В блоке
**Подписи скважин** можно включить или скрыть подписи, выбрать их цвет, шрифт
(Arial, Times или Courier) и размер. Настройки файла скважин сразу применяются
ко всем его скважинам и сохраняются вместе с проектом.

В контекстном меню папки, файла скважин или послойного куба команды
**Выбрать все** и **Отменить выбор** включают или выключают контейнер и все
вложенные объекты. Изменения видимости сохраняются вместе с проектом.
Меню **Tools → Тема приложения…** открывает отдельное окно выбора
светлой или тёмной темы. Тема меняет интерфейс и фон 3D-сцены и сохраняется
для приложения независимо от проекта.

- **Режим**: для облака и узлового куба — точки, сферы или объёмные ячейки;
  режим ячеек доступен, когда центры образуют достаточно плотные строки и слои
  XYZ без повторяющихся координат. Границы ячеек проходят посередине между
  центрами; отсутствующие ячейки остаются пустыми. Для поверхности и
  corner-point куба доступны поверхность, каркас, точки (углы ячеек) и сферы.
- **Форма точки**: круг или квадрат в плоском точечном режиме.
- **Цвет**: цвет заливки, а в режиме каркаса — цвет линий.
- **Размер точки**: диаметр заливки в пикселях, от 1 до 64.
- **Обводка**: включение, отдельный цвет и толщина от 0,5 до 20 пикселей.
  У плоских точек обводка добавляется снаружи, у поверхности показывает рёбра.
  В каркасном режиме доступна толщина линий. В режиме сфер обводка отключена;
  её настройки сохраняются при переключении обратно на точки.
  В режимах **Corner-point grid** и **Объёмные ячейки** флажок называется
  **Обводка призм** и запоминается независимо от обводки точек. Он сохраняется
  при перестроении сетки, смене палитры, переключении режимов и открытии проекта;
  цвет и толщина обводки также записываются в проект.
- **Прозрачность**: от 0% (непрозрачно) до 100% (полностью прозрачно);
  применяется и к однотонному цвету, и к палитре.
- **Сбросить настройки** возвращает стандартный вид выбранного объекта.

Кнопка **Настройка осей…** под таблицей свойств и пункт **View → Настройка осей…**
открывают отдельное окно. В нём можно показывать или скрывать координатные оси
с числовыми делениями и включать сетку. Оси строятся по границам видимых данных;
деления показывают исходные координаты даже при изменённом масштабе.
В этом же окне задаётся число знаков после запятой у подписей. Опция
**Округлять границы до круглых чисел** расширяет рамку осей до удобных делений
с шагом 1, 2 или 5 × 10ⁿ; точность подписей задаёт минимальный шаг.
Числовые подписи у общих углов не выводятся; при повороте камеры или изменении
размера окна плотность остальных подписей подстраивается под свободное место.
Множители X/Y/Z меняют пропорции всей сцены сразу: одинаковое преобразование
применяется ко всем объектам от общего начала координат. Значение 1× означает
исходный масштаб. Данные в таблицах не меняются; настройки осей сохраняются
в `project.json`.

**View → Отсечь объекты → Показать плоскость и отсечь** включает общую
виртуальную плоскость для всех видимых объектов. Плоскость можно перетаскивать
и поворачивать мышью в 3D-сцене. Пункт **Настроить плоскость…** открывает
окно с координатами центра, углами поворота вокруг X/Y/Z и кнопками сдвига:
U/V перемещают плоскость вдоль неё, N сдвигает параллельную плоскость по нормали.
Можно выбрать противоположную сторону отсечения. Положение и состояние
сохраняются в проекте. Геометрия и значения объектов при этом не меняются.

Кнопка **Настроить палитру…** открывает редактор окраски по числовому параметру.
Для облака точек доступны числовые столбцы таблицы, для corner-point куба —
индексы I/J/K и числовые параметры ячеек, для поверхности — высота Z.
В редакторе можно загрузить палитру Surfer `.CLR` версий 1–3, выбрать параметр,
перетаскивать пределы шкалы и цветовые узлы, вводить точные значения и позиции,
добавлять и удалять узлы, выбирать цвета, непрозрачность и интерполяцию.
Шкала значений может быть линейной или логарифмической (log10). Для log10
пределы должны быть положительными; нулевые и отрицательные значения
показываются серым цветом. Значения вне заданных пределов окрашиваются
крайними цветами. Кнопка
**Отключить палитру** возвращает однотонную окраску. Палитра целиком сохраняется
в проекте: исходный файл `.CLR` после загрузки больше не нужен.

Под цветовой полосой расположен **Фильтр отображения**. Включите его и задайте
интервал «от — до», чтобы показывать только данные с такими значениями; кнопка
**Диапазон по данным** возвращает границы параметра. Фильтр не меняет пределы
цветовой шкалы и исходные данные. У облаков скрываются точки, у кубов — ячейки,
у скважин — участки траектории; поверхность обрезается по границам интервала.
Фильтр контейнера применяется к дочерним объектам и сохраняется в проекте.

Изменения применяются сразу, сохраняют выбранный объект и положение камеры,
отмечают проект как изменённый. После `Ctrl+S` настройки восстанавливаются при
открытии проекта, в том числе после «Сохранить как». Для проектов без этих
настроек используются стандартные значения. Скрытому объекту тоже можно менять
стиль: он будет применён, когда объект станет видимым.

## Архитектура и хранение

- `models/project/Project.py` — дерево, поиск по UUID, операции над объектами,
  контроль принадлежности проекту, запрет циклов, признак изменений и жизненный цикл.
- `models/project/ProjectStorage.py` — чтение, проверка версии, миграция и запись
  проекта. Модель не зависит от Qt.
- `models/project/TableStorage.py` — таблицы в NPZ: числовые массивы без округления,
  текст в JSON, типы колонок, индексы и маски пропусков. Загрузка не использует pickle.
  Поддерживаются обычные типы импортируемого CSV и nullable-типы pandas; MultiIndex,
  category и прочие специальные типы требуют расширения сериализатора.
- `gui/MainWindow.py` — команды пользователя, обработка ошибок и сохранение сессии.
  Дерево хранит UUID, поэтому одноимённые объекты не смешиваются. Все операции
  интерфейса изменяют `Project`, а отображение строится по его состоянию.
- `gui/Viewer3D.py` — отображение облаков точек и поверхностей, очистка сцены
  при смене проекта, освобождение ресурсов VTK при закрытии.
- `models/Appearance.py` — неизменяемые настройки вида и их проверка;
  `Project.set_appearance` применяет изменения и учитывает их при сохранении.
- `models/ColorMap.py` — загрузка Surfer CLR, узлы, диапазон и таблица цветов.
- `models/CornerPointGrid.py` и `importers/GrdeclImporter.py` — геометрия
  corner-point ячеек и чтение GRDECL; `renderers/corner_point_renderer.py`
  формирует VTK-ячейки, объединяя совпадающие вершины соседних ячеек и
  сохраняя раздельными смещённые углы по разломам.
- `importers/PointCloudGridBuilder.py` — построение corner-point grid из центров
  ячеек CSV, распознавание рядов и распределение нерегулярных точек по ячейкам.
- `gui/dialogs/PaletteDialog.py` — редактор шкалы и цветовых узлов.
- `importers/ObjectFactory.py` — проверка и создание объектов выбранного типа
  из таблицы или готовой сетки; `models/Well.py`, `models/WellFile.py` и
  `models/DataCube.py` содержат методы соответствующих типов.
- `gui/custom_widgets/AppearanceEditor.py` — редактор вида выбранного объекта;
  `renderers/appearance.py` обновляет свойства существующего актора и отрисовку
  маркеров, не пересоздавая геометрию. Размеры задаются в пикселях экрана;
  вьювер использует FXAA, сохраняющий размеры рабочего viewport.

Формат проекта версии 4:

```text
project.json                 # Имя, версия, даты, дерево, UUID, флаги, ссылки на данные
source/<hash>/<имя файла>     # Побайтовые копии исходных файлов с исходным именем
work/<hash>.table.npz         # Полные таблицы облаков точек
work/<hash>.surface.npz       # Вершины, грани и нормали поверхностей
work/<hash>.corner.npz        # Пиллары, углы, маска и параметры corner-point куба
cache/                       # Резерв для производных данных
```

Ссылки на данные относительные. Сначала записываются данные, затем `project.json`
атомарно заменяется через временный файл на том же диске. При ошибке записи
предыдущая сохранённая версия остаётся доступна, а текущий проект остаётся
изменённым. Создание и «Сохранить как» готовятся во временной соседней папке;
неудачная попытка не мешает повторному сохранению в то же место.

Рабочие файлы названы по SHA-256 содержимого. Исходники сохраняют имя и содержимое;
хеш служит именем вложенной папки, чтобы разные исходники с одинаковым именем не
перезаписывали друг друга. Неизменённые данные не дублируются. После успешного
сохранения неиспользуемые файлы из `work/` и копии исходников из `source/`
удаляются; данные, на которые ссылаются другие объекты, остаются.
Если файл из `work/`, указанный в `project.json`, удалён, проект не открывается:
сообщение называет объект и отсутствующий файл. Восстановите этот файл из копии
папки проекта. Уже открытый в приложении проект при такой ошибке не заменяется.
Удаление копии исходного файла из `source/` не мешает открытию, пока сохранены
данные объекта в `work/`.

Проекты версии 2 восстанавливаются из указанных в них исходных файлов и при
сохранении обновляются до версии 4. Проекты версии 3 читаются вместе с их сохранёнными
данными и получают пустой Canvas. Если исходного файла нет у проекта версии 2, приложение сообщает
об ошибке: прежний формат не содержал самих данных. Неизвестные версии и типы,
повторяющиеся UUID и ссылки за пределы папки проекта отклоняются.

Для программного изменения таблицы после редактирования `cloud.dataframe` нужно
вызвать `project.mark_modified()`. У corner-point куба исходными данными служат
`cube.corner_grid` и его `properties`; таблица центров вычисляется из них.
Методы `add`, `remove`, `move`, `rename`,
`rename_project`, `set_visible` и `import_file` отмечают изменения сами.

## Canvas и машинное обучение

В центральной области находится **Canvas**: свободное поле с точечной
сеткой, карточками, заметками Markdown, цветными группами и направленными связями.
Схема и расположение сохраняются вместе с проектом. Перестановка карточек,
группировка и поясняющие стрелки не меняют результаты расчёта.

Над рабочей областью постоянно доступно меню вида: **Canvas и 3D рядом**,
**друг под другом**, **только Canvas**, **только 3D**, **3D в отдельном окне**.
Плавающий 3D использует dock-панель Qt; при закрытии она возвращается в общую область.
У карточки исходного объекта доступны **Показать в 3D**, **Приблизить**, **Скрыть** и EDA.
В исходных данных Canvas доступны также **Точки с настраиваемой сеткой**,
их отдельные слои и контейнер слоёв. Объект можно перетащить из дерева или
выбрать в карточке «Исходные данные»; карточка показывает количество исходных
точек и, для контейнера, слоёв.
Новый объект точек подключается вместо куба ко входу **Куб / точки** процесса
создания каталога. Предикторы берутся из исходных строк; сетка отображения,
интерполяция и видимость слоёв не меняют обучающие данные. В «Настроить патчи…»
для такого источника задаются число ближайших исходных точек (по умолчанию 1)
и максимальное расстояние до отметки скважины (0 — без ограничения). Для
контейнера используются все слои и общие выбранные параметры. Соседи хранятся
в порядке расстояния, а не как ячейки регулярного куба; недостающие соседи и
NoData сохраняются с маской. Идентификаторы исходных слоёв и диапазоны строк
записываются в происхождение каталога. Правила разбиения по скважинам прежние.
Можно показать куб, весь файл скважин или отдельную скважину. Выбор строки каталога
показывает её точку и фактические ячейки патча в 3D, сохраняя доступ к Canvas.

1. Используйте объекты куба и **файла скважин** проекта с колонкой классов.
   Откройте **Шаблоны → Оценка прогнозной силы**.
   В карточках источников справа выберите объекты; в «Каталоге образцов» укажите
   колонку класса, параметры куба и размер патча в порядке **K,J,I**. Кнопка
   **Настроить патчи…** открывает список предикторов и диапазоны соседей по X/I, Y/J, Z/K.
2. В блоке **Прогнозная сила модели** задайте N повторов, долю Test (по умолчанию 25%)
   и параметры Random Forest. Нажмите **▶ Всё**, чтобы собрать каталог и выполнить
   повторную проверку способности предсказывать классы в новых скважинах. В каждом
   повторе скважины заново делятся на Train/Test, новая модель обучается на 75%,
   затем проверяется на оставшихся 25%. **▶ Ветку** выполняет
   выбранный блок и его зависимости. Расчёт идёт в фоновом потоке; его можно остановить.
3. Дважды щёлкните карточку для просмотра результата. Каталог поддерживает сортировку,
   поиск, экспорт текущих строк в CSV, просмотр трёх срезов патча и масок пропусков.
   Кнопки **Включить / Исключить** отбирают выделенные строки, а при отсутствии
   выделения — все строки текущего поиска. Отбор сохраняется в объекте каталога и
   помечает последующие расчёты для пересчёта. **Экспорт соседей** создаёт длинную
   таблицу с Source_X/Y/Z, Source_WellName, Cube_X/Y/Z, Dist и Neighbor_Index,
   совместимую по смыслу с экспортом GetParamsFromCUB. Это дополнительный экспорт;
   вычисления работают напрямую с объектами проекта, без промежуточного CSV-импорта.
   Отчёт прогнозной силы показывает сводную метрику и её разброс по повторам,
   результаты каждой тестовой скважины, состав Train/Test и матрицы ошибок.
4. Вкладка **Запуски** хранит прежние результаты. Изменение входных данных или
   параметров помечает зависимые блоки как требующие пересчёта. Неизменившиеся
   результаты используются повторно; старые результаты сохраняются отдельными объектами.
   Для прежней схемы «разделение → обучение → тест / SHAP / куб» выберите каталог
   и нажмите **Шаблоны → Перестроить текущую схему для оценки**. Источники, каталог,
   параметры модели и прежние результаты сохраняются; изменение схемы отменяется Ctrl+Z.

Колесо меняет масштаб, средняя кнопка перемещает поле, левая выделяет карточки рамкой.
Карточку можно перемещать за её тело и менять её размер за правый нижний угол.
Пункт контекстного меню **Сгруппировать выделенное** объединяет карточки для совместного
перемещения. **Ctrl+Z / Ctrl+Y** отменяют и повторяют изменения схемы, **Delete** удаляет
выделенные карточки или связи. Объекты можно перетаскивать из дерева проекта или
добавлять через его пункт **Добавить на Canvas**. Правый порт блока соединяется
перетаскиванием с левым портом другого блока. Кнопка **Связь…** также добавляет
поясняющие пунктирные стрелки с подписями. Вычислительные связи проверяют типы,
единственность входа и отсутствие циклов; поясняющие связи могут образовывать любые схемы.

`TrainingSet` — самостоятельный объект проекта. Каталог содержит стабильный `sample_id`,
UUID скважины, исходную строку, XYZ, класс, индекс ячейки, расстояние привязки, долю данных
и причину исключения. Сохраняются UUID и имя исходного файла скважин, отдельные
координаты скважины и куба, остальные параметры скважины с префиксом Source_,
координаты всех соседей и их индексы. Массивы имеют форму `[образец, параметр, K, J, I]`; маска различает
исходный NoData, край куба и неактивную ячейку. Статистика показывает уникальные значения,
число пропусков и исходные маркеры NoData; таблица признаков позволяет запускать EDA.
`dataset[i]` выдаёт патч, маску, строковую метку, числовой `target` и идентификаторы;
`dataset.usable_samples` — индексируемое представление только готовых образцов.

Патч задаётся размером **K,J,I** (нечётные числа от 1 до 31) или шестью границами
**Imin,Imax,Jmin,Jmax,Kmin,Kmax** (смещения от −63 до 63). Диапазоны могут быть
несимметричными и иметь чётную длину. В режиме **Пропуски за границей** отсутствующие
ячейки маскируются. Режим **Повтор края (MATLAB)** прижимает индексы к границам,
воспроизводя повторение крайних значений из `findNeighborsByOffsets`.
Поддерживаются узловая сетка с равномерными координатными осями (в том числе
с отсутствующими узлами) и corner-point grid. Отсутствующие узлы внутри сетки
остаются пропусками; привязка к соседнему существующему узлу через пустоту не выполняется.
В corner-point сетке точка привязывается к содержащей её активной ячейке, без
переноса через разрывы на ближайший центр. Патчи имеют одинаковую форму массива;
их физические размеры на нерегулярной геометрии могут различаться. Патчи хранятся в RAM
и сохраняются числовыми массивами; подготовку очень больших выборок нужно соотносить
с доступной памятью. Пересэмплирование на единый физический шаг пока не реализовано.

Алгоритм в текущем этапе — Random Forest. Можно использовать все значения патча
или среднее, стандартное отклонение, минимум, максимум и долю пропусков по каждому
параметру. Пропуски заполняются медианами **только обучающих образцов**. Разделение
делается по именам целых скважин **внутри каждого исходного файла**. По умолчанию
75% скважин идут в обучение и 25% в тест; число тестовых скважин округляется
к ближайшему целому с минимумом 1 в каждой части. Фактические доли, имена и UUID
записываются в отчёт. Учитываются скважины с готовыми выбранными образцами.
Для файла с единственной такой скважиной можно выбрать ошибку или оставить её в
обучении; обе части итоговой выборки должны быть непустыми. Такое разделение не гарантирует
пространственного разделения перекрывающихся патчей соседних скважин.

**Шаблоны → Оценка прогнозной силы** создаёт цепочку из объектов
куба и файла скважин, процесса **Создание каталога образцов**, отдельной карточки
данных **Каталог образцов** и блока **Прогнозная сила модели**. Данные отображаются
со скошенными сторонами, процессы — прямоугольниками. Настройки извлечения патчей
относятся к процессу создания; готовый каталог открывается двойным щелчком
по карточке данных. Эта карточка ссылается на результат без копирования выборки.
Вместо одного файла можно выбрать папку файлов скважин. Настройте N повторов
(например, 1000), долю теста, seed и параметры выбранной модели. В каждом повторе
имена скважин каждого файла выбираются заново, медианы и модель обучаются только
на Train, затем сохраняются матрица ошибок и macro F1 **каждой тестовой скважины**.
Отчёт содержит все разбиения, seed каждого повтора, метрики, число проверок каждой
скважины, среднее, стандартное отклонение, минимум, максимум и квантили 5/50/95%.
Для выбранной строки метрик можно открыть соответствующую матрицу ошибок.
Входом блока является полный подготовленный каталог; подключение уже отделённой
части Train/Test отклоняется, чтобы не разделять данные второй раз.

Основная метрика: в каждом повторе macro F1 сначала считается для каждой скважины
Test, затем усредняется с равным весом скважин. Прогнозная сила представлена
средним и стандартным отклонением этой метрики по успешным повторам. Это позволяет
оценить качество на новых скважинах, независимо от различий их длины. Отдельно
показаны macro F1 и accuracy по всем тестовым образцам вместе; их матрицы ошибок
сохранены для каждого успешного повтора.

Обучение итоговой модели и применение ко всему источнику доступны отдельной
веткой: выделите конечный каталог → **Шаблоны → Добавить итоговую модель и прогноз**.
Итоговая модель обучается на всех выбранных готовых образцах с сохранением
подготовки. Модели проверочных повторов остаются только в ветке статистической
оценки. Сценарий MVP, CSV, мини-диаграммы и просмотр образцов в 3D описаны
в `docs/canvas_mvp.md`.

По умолчанию macro F1 усредняется по классам, встречающимся в истинных или
предсказанных значениях данной скважины. Опция **Macro F1 по всем классам каталога**
включает отсутствующие классы с F1=0. Оба правила явно записываются в результат.
Повторы с невозможным обучением (например, один класс в Train) отмечаются ошибкой
и сохраняют своё разбиение, не подменяя неудачные попытки новыми. При остановке
сохраняется статистика завершённых повторов; прерванный расчёт не считается
завершённым результатом кеша. Отчёты содержат список исходных sample_id.

Протокол оценки описан в `docs/predictive_power.md`, сопоставление извлечения
патчей с MATLAB — в `docs/matlab_sampling_comparison.md`.
Процессы подготовки каталога (масштабирование, распределения, дисбаланс),
сравнение Train/Test и выбор альтернативных моделей описаны в
`docs/catalog_preparation.md`. Быстрое добавление: выделите каталог и выберите
**Шаблоны → Добавить подготовку выбранного каталога**. Все преобразования
настраиваются только по Train каждого повтора; Test не балансируется.
Проверка реальных исходных файлов Merzl_srb и настройки импорта описаны
в `docs/merzl_srb_sources.md`.

Модели, выборки и отчёты хранятся в `work/*.calculation.zip`: JSON, таблицы NPZ и
числовые массивы без pickle. История сохраняет настройки, отпечатки входов, время и
UUID результата. Повторное открытие не требует переобучения и повторного SHAP-расчёта.
В дереве проекта есть папка **Canvas**: результаты расчётов (каталоги и подкаталоги,
модели, отчёты, преобразованные точки и прогнозные кубы) сохраняются её потомками.
При открытии старого проекта ранее созданные результаты автоматически переносятся
в эту папку с сохранением UUID и связей на схеме. Исходные объекты остаются на месте.
Для новых ML-блоков предусмотрен общий реестр описаний `models/Canvas.py` и отдельный
от Qt исполнитель `models/pipeline.py`.

## Проверка

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -B -m tests.vtk_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_appearance_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_transparency_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_corner_point_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_layered_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_clipping_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_canvas_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_canvas_mvp_smoke
```

Основной набор проверяет сохранение и повторное открытие, перенос копии,
точность чисел, миграцию, целостность дерева, ошибки записи, импорт и действия Qt.
Он не требует OpenGL. Отдельная проверка `vtk_smoke` кратковременно открывает
настоящие окна Windows и проверяет восстановление облака точек и поверхности
в Qt/VTK после закрытия приложения.

`vtk_appearance_smoke` проверяет пиксели настоящего Qt/VTK-рендера: заливку,
обводку и её толщину, круги/квадраты/сферы, смену размеров окна, переключение
режимов поверхности, палитру, прозрачность, масштаб и сохранение камеры.
Требуется рабочий стол Windows.

`vtk_transparency_smoke` проверяет пересечение двух полупрозрачных поверхностей
с разными палитрами и облако точек внутри полупрозрачной оболочки.
