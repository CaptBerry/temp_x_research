Приложение разрабатывается для удовлетворения потребностей в области анализа данных и визуализации расчетов.

**Основные задачи** это машинное обучение и классификация данных скважин, по данным геофизики

**Второстепенные задачи** - работа с данными, сортировка, анализ, обработка;
                            построение структуры по данным сейсмики или по данным ЗСБ.

Stack:
- Python 3.12
- PyQt6
- PyVista
- NumPy
- Pandas

## Запуск

Из корня репозитория, PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Если окружение уже настроено, достаточно последней команды. Для 3D нужен рабочий
OpenGL-контекст Windows. Платформа Qt `offscreen` используется только в тестах
интерфейса с заменой 3D-вьювера.

## Работа с проектом

1. **Файл → Создать проект**: выбрать родительскую папку и ввести имя.
2. **Импортировать объект**: выбрать тип в выпадающем списке, затем CSV/TXT/DAT,
   разделитель и наличие заголовка, назначить три разные числовые колонки X/Y/Z
   и дополнительные параметры. Для скважины и файла скважин нужно выбрать колонку
   идентификатора; для поверхности — вид («обычная», «разрез», «трещина»).
   Для файлов без заголовка используются имена колонок `0`, `1`, `2` и т. д.
   Поверхность можно также импортировать из VTK/VTP/STL/OBJ/PLY/VTU/VTS.
   При импорте поверхности из таблицы используется геометрия XYZ; дополнительные
   столбцы не назначаются параметрами поверхности. XYZ-точки триангулируются
   автоматически; если нужно сохранить точную топологию разреза или трещины,
   импортируйте готовую сетку.
   Для **куба данных** CSV/TXT/DAT трактуется как облако **центров ячеек**.
   В поле «Сетка куба» по умолчанию выбран corner-point grid: если XYZ образуют
   ряды и слои, одна точка соответствует одной ячейке; пропущенные ячейки
   неактивны. Для нерегулярного облака строится равномерная сетка по габаритам
   точек. Число ячеек X/Y/Z можно задать вручную или оставить «Авто»; параметры
   точек в общей ячейке усредняются, а `N_POINTS` хранит их количество.
   Флажок «Соединять существующие ячейки» по умолчанию расширяет ячейки через
   пустые интервалы до общей границы. Новые ячейки не добавляются, исходные
   параметры сохраняются. Для разреженного облака расширение выполняется вдоль
   преобладающего горизонтального направления и по вертикали в каждом столбце;
   между несопоставимыми рядами пустоты могут остаться.
   Исходные координаты центров сохраняются как `CENTER_X/Y/Z` (при нескольких
   точках в ячейке — их средние). При неравномерном расстоянии между рядами
   геометрический центр построенной ячейки может отличаться от исходной точки.
   Если по оси есть лишь один уровень центров, её толщину задаёт поле
   «Размер ячейки по одиночной оси». Границы между рядами ставятся посередине
   между соседними центрами; геологические разломы и наклонные пиллары из одних
   центров автоматически не восстанавливаются. Для прежнего отображения без
   ячеек есть режим «Только точки».
   Режим **«Послойная модель (кровля/подошва)»** создаёт один общий узел куба и
   дочерний corner-point куб для каждого значения выбранной колонки слоя.
   Выберите колонки X, Y, слоя, кровли и подошвы; `layer`, `AbsRoof` и `AbsBase`
   распознаются автоматически. Геометрия каждой ячейки строится между кровлей
   и подошвой, параметры строк остаются доступными для окраски. Слои можно
   независимо показывать и скрывать в дереве; проект сохраняет их отдельно.
   Для нерегулярной XY-сетки число ячеек X/Y можно задать вручную. Высоты углов
   общих ячеек усредняются из соседних значений кровли и подошвы.
   Для **куба данных** можно также выбрать `.grdecl`: тип переключится на куб,
   а геометрия `SPECGRID`/`DIMENS`, `COORD`, `ZCORN`, маска `ACTNUM` и числовые
   параметры ячеек будут прочитаны автоматически. Предпросмотр показывает центры
   активных ячеек и индексы I/J/K; назначать колонки вручную не требуется.
3. В контекстном меню дерева можно создавать вложенные папки, импортировать
   данные в выбранную папку, переименовывать и удалять объекты. Флажок папки
   управляет видимостью всего её содержимого; настройки видимости детей сохраняются.
4. **Сохранить** (`Ctrl+S`) записывает данные и структуру. Звёздочка в заголовке
   показывает несохранённые изменения. **Сохранить как** создаёт самостоятельную
   копию в новой или пустой папке и переключает работу на неё.
5. При закрытии окна, закрытии проекта, создании или открытии другого проекта
   предлагается сохранить изменения, отбросить их или отменить действие.
   Ошибка сохранения также отменяет закрытие.
6. При следующем запуске восстанавливается последний открытый проект.
   **Закрыть проект** очищает текущую сессию; после этого автоматического открытия
   не будет. Вручную проект открывается через его `project.json`.

Для переноса проекта нужно копировать **всю папку проекта**. После сохранения
исходный CSV больше не требуется для восстановления данных.

Типы объектов: **скважина** хранит упорядоченную траекторию, ID и числовые
параметры каждой точки; **файл скважин** группирует скважины по ID и позволяет
получить скважину по идентификатору; **куб данных** хранит 3D-узлы и параметры
либо corner-point grid с пилларами, независимыми глубинами углов, маской активности
и параметрами ячеек. Куб поддерживает разрезы по X/Y/Z, а для полного набора
регулярных узлов — построение плотного массива;
**поверхность** хранит треугольную сетку и её вид, вычисляет площадь; **облако
точек** остаётся свободным набором точек. Тип, параметры и дочерние скважины
сохраняются в проекте. Узловой куб отображается точками, corner-point grid —
объёмными ячейками с рёбрами, скважина — линией траектории.

GRDECL поддерживает повторения вида `N*значение`, включая `D`-экспоненту,
`INCLUDE` с путями относительно файла и числовые массивы параметров длиной
`Nx×Ny×Nz`. Для файлов `INCLUDE` используется порядок следования данных I, J, K
с самой быстрой осью I. Отсутствующий `ACTNUM` означает, что все ячейки активны.
Геометрия и параметры копируются в проект, поэтому после сохранения исходный
GRDECL и вложенные файлы не нужны. Операции `MAPAXES`, `BOX`, `EQUALS`, `COPY`,
`ADD`, `MULTIPLY`, локальное уточнение сетки и бинарный EGRID пока не
поддерживаются: импорт таких геометрических преобразований прерывается с ошибкой.

### Настройки отображения

Выберите объект в дереве. Справа, под таблицей свойств, находится панель
**Отображение**. После импорта облако точек выбирается автоматически.
Если выбран **файл скважин** или **послойный куб**, изменения этой панели,
включая палитру, сразу применяются ко всем дочерним скважинам или слоям.
В редакторе палитры контейнера доступны только числовые параметры, общие для
всех его дочерних объектов. Настройки контейнера и детей сохраняются в проекте;
добавленный позднее объект наследует текущий вид контейнера.

- **Режим**: для облака и узлового куба — точки или сферы; для поверхности и
  corner-point куба — поверхность, каркас, точки (углы ячеек) или сферы.
- **Форма точки**: круг или квадрат в плоском точечном режиме.
- **Цвет**: цвет заливки, а в режиме каркаса — цвет линий.
- **Размер точки**: диаметр заливки в пикселях, от 1 до 64.
- **Обводка**: включение, отдельный цвет и толщина от 0,5 до 20 пикселей.
  У плоских точек обводка добавляется снаружи, у поверхности показывает рёбра.
  В каркасном режиме доступна толщина линий. В режиме сфер обводка отключена;
  её настройки сохраняются при переключении обратно на точки.
- **Прозрачность**: от 0% (непрозрачно) до 100% (полностью прозрачно);
  применяется и к однотонному цвету, и к палитре.
- **Сбросить настройки** возвращает стандартный вид выбранного объекта.

Блок **Масштаб осей проекта** доступен независимо от выбранного объекта.
Коэффициенты X/Y/Z изменяют пропорции координатных осей всей сцены сразу:
одинаковое преобразование применяется ко всем облакам и поверхностям от общего
начала координат. Значение 1× соответствует исходному масштабу. Числа в таблицах
и геометрия объектов не изменяются; масштаб сохраняется в `project.json`.

Кнопка **Настроить палитру…** открывает редактор окраски по числовому параметру.
Для облака точек доступны числовые столбцы таблицы, для corner-point куба —
индексы I/J/K и числовые параметры ячеек, для поверхности — высота Z.
В редакторе можно загрузить палитру Surfer `.CLR` версий 1–3, выбрать параметр,
перетаскивать пределы шкалы и цветовые узлы, вводить точные значения и позиции,
добавлять и удалять узлы, выбирать цвета, непрозрачность и интерполяцию.
Шкала значений может быть линейной или логарифмической (log10). Для log10
пределы должны быть положительными; нулевые и отрицательные значения
показываются серым цветом. Значения вне заданных пределов окрашиваются
крайними цветами. Кнопка
**Отключить палитру** возвращает однотонную окраску. Палитра целиком сохраняется
в проекте: исходный файл `.CLR` после загрузки больше не нужен.

Изменения применяются сразу, сохраняют выбранный объект и положение камеры,
отмечают проект как изменённый. После `Ctrl+S` настройки восстанавливаются при
открытии проекта, в том числе после «Сохранить как». Для проектов без этих
настроек используются стандартные значения. Скрытому объекту тоже можно менять
стиль: он будет применён, когда объект станет видимым.

## Архитектура и хранение

- `models/project/Project.py` — дерево, поиск по UUID, операции над объектами,
  контроль принадлежности проекту, запрет циклов, признак изменений и жизненный цикл.
- `models/project/ProjectStorage.py` — чтение, проверка версии, миграция и запись
  проекта. Модель не зависит от Qt.
- `models/project/TableStorage.py` — таблицы в NPZ: числовые массивы без округления,
  текст в JSON, типы колонок, индексы и маски пропусков. Загрузка не использует pickle.
  Поддерживаются обычные типы импортируемого CSV и nullable-типы pandas; MultiIndex,
  category и прочие специальные типы требуют расширения сериализатора.
- `gui/MainWindow.py` — команды пользователя, обработка ошибок и сохранение сессии.
  Дерево хранит UUID, поэтому одноимённые объекты не смешиваются. Все операции
  интерфейса изменяют `Project`, а отображение строится по его состоянию.
- `gui/Viewer3D.py` — отображение облаков точек и поверхностей, очистка сцены
  при смене проекта, освобождение ресурсов VTK при закрытии.
- `models/Appearance.py` — неизменяемые настройки вида и их проверка;
  `Project.set_appearance` применяет изменения и учитывает их при сохранении.
- `models/ColorMap.py` — загрузка Surfer CLR, узлы, диапазон и таблица цветов.
- `models/CornerPointGrid.py` и `importers/GrdeclImporter.py` — геометрия
  corner-point ячеек и чтение GRDECL; `renderers/corner_point_renderer.py`
  формирует VTK-ячейки, объединяя совпадающие вершины соседних ячеек и
  сохраняя раздельными смещённые углы по разломам.
- `importers/PointCloudGridBuilder.py` — построение corner-point grid из центров
  ячеек CSV, распознавание рядов и распределение нерегулярных точек по ячейкам.
- `gui/dialogs/PaletteDialog.py` — редактор шкалы и цветовых узлов.
- `importers/ObjectFactory.py` — проверка и создание объектов выбранного типа
  из таблицы или готовой сетки; `models/Well.py`, `models/WellFile.py` и
  `models/DataCube.py` содержат методы соответствующих типов.
- `gui/custom_widgets/AppearanceEditor.py` — редактор вида выбранного объекта;
  `renderers/appearance.py` обновляет свойства существующего актора и отрисовку
  маркеров, не пересоздавая геометрию. Размеры задаются в пикселях экрана;
  вьювер использует FXAA, сохраняющий размеры рабочего viewport.

Формат проекта версии 3:

```text
project.json                 # Имя, версия, даты, дерево, UUID, флаги, ссылки на данные
source/<hash>.<extension>     # Копии доступных исходных файлов
work/<hash>.table.npz         # Полные таблицы облаков точек
work/<hash>.surface.npz       # Вершины, грани и нормали поверхностей
work/<hash>.corner.npz        # Пиллары, углы, маска и параметры corner-point куба
cache/                       # Резерв для производных данных
```

Ссылки на данные относительные. Сначала записываются данные, затем `project.json`
атомарно заменяется через временный файл на том же диске. При ошибке записи
предыдущая сохранённая версия остаётся доступна, а текущий проект остаётся
изменённым. Создание и «Сохранить как» готовятся во временной соседней папке;
неудачная попытка не мешает повторному сохранению в то же место.

Файлы данных названы по SHA-256 содержимого. Неизменённые данные не дублируются.
Неиспользуемые файлы прежних сохранений пока остаются на диске: автоматическая
очистка не реализована, поэтому при многократном изменении таблиц размер папки растёт.

Проекты версии 2 восстанавливаются из указанных в них исходных файлов и при
сохранении обновляются до версии 3. Если исходного файла нет, приложение сообщает
об ошибке: прежний формат не содержал самих данных. Неизвестные версии и типы,
повторяющиеся UUID и ссылки за пределы папки проекта отклоняются.

Для программного изменения таблицы после редактирования `cloud.dataframe` нужно
вызвать `project.mark_modified()`. У corner-point куба исходными данными служат
`cube.corner_grid` и его `properties`; таблица центров вычисляется из них.
Методы `add`, `remove`, `move`, `rename`,
`rename_project`, `set_visible` и `import_file` отмечают изменения сами.

## Проверка

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -B -m tests.vtk_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_appearance_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_transparency_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_corner_point_smoke
.\.venv\Scripts\python.exe -B -m tests.vtk_layered_smoke
```

Основной набор проверяет сохранение и повторное открытие, перенос копии,
точность чисел, миграцию, целостность дерева, ошибки записи, импорт и действия Qt.
Он не требует OpenGL. Отдельная проверка `vtk_smoke` кратковременно открывает
настоящие окна Windows и проверяет восстановление облака точек и поверхности
в Qt/VTK после закрытия приложения.

`vtk_appearance_smoke` проверяет пиксели настоящего Qt/VTK-рендера: заливку,
обводку и её толщину, круги/квадраты/сферы, смену размеров окна, переключение
режимов поверхности, палитру, прозрачность, масштаб и сохранение камеры.
Требуется рабочий стол Windows.

`vtk_transparency_smoke` проверяет пересечение двух полупрозрачных поверхностей
с разными палитрами и облако точек внутри полупрозрачной оболочки.
